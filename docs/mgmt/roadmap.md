# InnoSkill 交付路线图（建议稿）

## 1. 目标与计划约束

- 依据：[问题定义](../requirements/problem_definition.md)。
- **预计交付目标：2026-12-31**，具体交付范围与验收标准仍待确认。
- 该日期不等于正式公开发布日期；发布时间需另行决策。
- 本文仅提出阶段和推进门槛，不虚构阶段日期、人员投入或完成百分比。
- 不声称已有可运行产品、已完成外部兼容或商业闭环。
- 产品目标能力不等于首期承诺；计划以签署的首期需求基线为准。
- 阶段可按依赖交错推进，但未决规则不能通过并行开发绕过。

## 2. 范围管理与协作建议

- 产品需求参考[需求规格](../requirements/product_requirements.md)，需求 ID 用于持续追踪。
- 建议先验证创作、发布、发现、阅读、平台运行与反馈闭环。
- 收费、付费 Fork、外部接入等目标能力需分别评估风险，再决定是否进入首期。
- 首期明确包含项、排除项、支持工具与版本、质量门槛、验收责任及证据形式。
- 建议职责：产品负责人协调规则，技术负责人维护架构，测试负责人组织验证。
- 教师与职前教师代表参与价值验收；版权、隐私和结算问题需相应专业评审。
- 上述为职责建议，不代表已经配备团队或指定人员。
- 需求变更须说明价值、工作量、依赖和风险，批准后同步文档与测试基线。

## 3. 阶段建议与退出门槛

| 阶段 | 主要工作 | 产出 | 退出门槛 |
| --- | --- | --- | --- |
| A：问题与范围确认 | 访谈教师和职前教师，验证创作、接入、学习与反馈痛点 | 调研证据、首期候选范围、业务规则清单 | 关键问题有证据；首期范围及验收负责人确认 |
| B：原型与经验表达 | 用真实经验验证模板、编辑、AI 辅助与文件导入方案 | 原型、Skill 样例、方法表达标准 | 创作者可表达关键判断；学习者能理解方法；门槛经批准 |
| C：核心社区与运行闭环 | 按批准范围建立发布、发现、阅读、运行与反馈流程 | 可验收闭环、版本与授权机制、测试证据 | 核心用户流程通过；权限与运行失败处理可验证 |
| D：外部接入与商业验证 | 验证批准工具及免费、收费、Fork、计量与收益场景 | 兼容清单、商业规则、对账与权限证据 | 范围内兼容通过；账务与授权准确；阻塞规则已解决 |
| E：交付验收与移交 | 用户代表验收，整理限制、风险和运行说明 | 验收报告、交付清单、已知问题与移交资料 | 约定范围通过并签署；残余风险有明确处置 |

阶段 D 中未纳入首期的能力，只做调研或后续规划，不作为本次交付的已完成能力。

## 4. 各阶段重点检查

### A：锁定需求而非扩张承诺

- 明确用户痛点仍是待验证假设，避免以资源数量替代用户价值证据。
- 决定首期是否包含收费、Token 计费、Fork 与哪些外部工具。
- 为未决规则指定责任角色和决策记录，形成可评审的验收条件。

### B：验证 Skill 能否承载教师智慧

- 明确 Skill 格式、方法、约束、依赖和运行权限的候选规范。
- 对比创作方式的完成难度；确认哪些方式进入首期，哪些保留为目标能力。
- 验证学习者理解与迁移，而不只检查最终生成结果是否好看。

### C：验证核心流程与可信边界

- 参照[架构草案](../software/architecture.md)，先落实版本、授权与外部调用边界。
- 在真实代表性场景中验证费用提示、运行状态与 Issue 反馈。
- 处理越权、危险上传、运行失败与敏感数据泄露，不以演示成功代替测试。

### D：分别验证兼容和商业政策

- 外部目标包括 WorkBuddy、Codex、Claude Code、pi-coding-agent、dsh、zcode。
- 名单不是兼容承诺；逐一确定实际支持版本、接入方式、限制与验证证据。
- 收费机制先明确购买授权、抽成、Token 计量、退款及结算，再实现和验收。
- 单层衍生明确 a+b 标价和分项归属；净实收与多层规则不能自行推导。

### E：交付不等于公开发布

- 由目标用户完成代表性任务，检查范围、教学价值与系统行为。
- 交付说明区分可用能力、已知限制、暂不支持项与后续目标。
- 上线或公开发布还需确认运营、治理、服务支持及风险处置准备情况。

## 5. 依赖与未决事项

| 关键依赖 | 对计划的影响 |
| --- | --- |
| Skill 技术规范（BR-01） | 阻塞上传、编辑一致性、运行与外部接入验收 |
| 版权、访问与衍生授权（BR-02、03） | 阻塞付费阅读、导出、Fork 与再销售 |
| 交易、计量、退款（BR-04～06） | 阻塞准确扣费、收益与结算验收 |
| 衍生链及生命周期（BR-07、08） | 阻塞多层、多来源、改价与下架处置 |
| 数据与治理（BR-09） | 影响真实用户试用、日志、安全和运营边界 |
| 范围与质量基线（BR-10） | 未确认则无法判断目标日期前是否具备交付条件 |

未决项编号与需求规格一致；当前不补造规则结论或决策截止日期。

## 6. 主要风险与应对

| 风险 | 影响 | 建议应对 / 验收证据 |
| --- | --- | --- |
| 首期范围过大 | 交付失焦，目标日期承压 | 先签署闭环范围；范围调整保留批准记录 |
| 经验无法清晰表达 | 产品变成普通结果生成工具 | 教师样例与学习迁移验证；调整模板及方法表达标准 |
| AI 输出不稳定 | 教学可用性与信任下降 | 明确适用边界、教师复核与失败提示；保留评价证据 |
| 工具兼容差异 | 接入失败或承诺失实 | 逐工具验证；明确版本、能力损失和不支持项 |
| 版权和付费阅读冲突 | 侵权、内容泄露及争议 | 分离访问与衍生许可；权限负向测试与争议流程 |
| 收益和扣费规则不清 | 错扣款、错误分配或无法对账 | 批准公式与账务示例；幂等、退款及对账专项验证 |
| 学生数据及执行安全 | 隐私泄露或权限越界 | 脱敏试用、最小权限、运行隔离与安全检查 |
| 审核和运营职责缺位 | 下架、侵权与交易争议无法处理 | 明确责任、处理流程与审计；移交前验证准备度 |

## 7. 交付验收清单

- 范围：列出首期纳入的 PR ID、排除项、工具版本和未决规则处置。
- 用户：教师与职前教师代表完成约定任务，并提供创作、使用及学习反馈。
- 功能：按[测试策略](../software/testing_strategy.md)提供追踪矩阵与可复现证据。
- 商业：若纳入，核对标价、抽成、Token、收益归属、授权与退款；不混同归属和净收入。
- 安全：确认关键权限、隐私、上传和执行边界通过，重大风险没有被静默接受。
- 质量：达到批准后的指标；未设阈值时不能声称达到量化目标。
- 移交：提供实际可用的操作、限制、支持与恢复说明；命令待实现后验证再编写。
- 签署：未通过项、残余风险及处理责任清晰，由相应负责人确认是否允许交付。
- 目标管理：若证据显示无法在 2026-12-31 前达到约定范围，及时提出范围或计划调整供决策。
