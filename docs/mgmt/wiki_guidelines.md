# Wiki 维护与发布说明

## 内容分工

- **仓库 README / docs**：正式需求、架构、测试、安全、许可和贡献规则，随代码评审与版本管理。
- **Wiki**：FAQ、教学经验、外部工具接入经验、会议纪要和方案讨论。
- Wiki 中形成正式决定后，应通过 PR 更新仓库文档；讨论记录不直接改变业务规则。

当前 `docs/wiki/` 是本地草稿目录，不是已发布的 GitHub Wiki。仓库没有配置远程地址，不能生成真实 Wiki 链接或声称 Wiki 已开启。

## 建议页面

| 页面 | 内容 | 当前状态 |
| --- | --- | --- |
| Home | 入口与阅读导航 | 已有本地草稿 |
| FAQ | 产品定位与常见问题 | 已有本地草稿 |
| Teaching-Experience | 脱敏教学案例与经验表达 | 待有真实材料后建立 |
| Integration-Notes | 按工具、版本记录接入经验 | 待完成实际测试后建立 |
| Meeting-Notes | 会议时间、参与者、决定、待办 | 待真实会议后建立 |

不要为了填满页面而编造会议、测试结果或经验案例。

## 发布步骤

1. 维护者确定实际 GitHub 仓库地址，并确认账号权限及 Wiki 可用性。
2. 在 GitHub 创建 Wiki 首页，确认独立 Wiki 仓库存在。
3. 另行克隆该仓库的 `.wiki.git` 仓库；主仓库的 clone 不会自动下载 Wiki。
4. 将本地草稿复制到 Wiki 仓库，改写链接后提交与推送。本文不提供虚构的 owner/repo 命令。
5. 在 Wiki 首页补充主仓库 README 与正式文档的真实链接，在 README 补充真实 Wiki 地址。
6. 确认权限设置，原则上仅允许受信任协作者编辑，并保留修改历史。

## 链接与同步

本地草稿使用仓库相对链接。发布到独立 Wiki 后，`../../README.md` 等相对路径不再指向主仓库，应替换为真实仓库文档 URL；页面间链接也需按 Wiki 结构调整。

正式发布后应确定内容主源：建议以线上 Wiki 为 FAQ 和经验的主源，仓库只保留发布说明与必要导出，避免两套内容无规则地分叉。正式需求仍以仓库为主源。

## 编辑检查

- 注明适用工具和版本；未验证的信息明确标注。
- 教学案例脱敏，并确认分享权限。
- 会议纪要区分讨论、决定与待办，不杜撰参与者或责任人。
- 不在 Wiki 存放凭据、安全漏洞细节或受限制的收费 Skill 全文。
- 页面加入首页导航；过时内容标注状态并链接替代说明。
