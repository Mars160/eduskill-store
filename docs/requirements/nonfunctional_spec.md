# InnoJudge 非功能需求规范

本文对应 FURPS 中的 URPS（非功能性），F 见[功能需求规范](functional_spec.md)。

## 1. 非功能需求（URPS）

### U：易用性

| 编号 | 需求与验收标准 |
| --- | --- |
| NFR-U-01 | 教师与评分员分别试用，各至少 5 人；阅读简要指引后，至少 80% 能独立完成建任务或评分提交 |
| NFR-U-02 | 上传、保存和评估显示明确状态；失败说明原因，不将未评估显示为 0 分 |
| NFR-U-03 | 教师端区分人工分与 AI 分；评分点可跳转证据片段，无证据时明确提示 |

### R：可靠性

| 编号 | 需求与验收标准 |
| --- | --- |
| NFR-R-01 | AI 超时、失败或重跑不阻断人工评分，不改写已提交人工记录 |
| NFR-R-02 | 同一评分重复提交不产生重复有效记录；服务重启后，已确认保存的评分仍可读取 |
| NFR-R-03 | 超满分、分值合计错误或时间越界的 AI 输出不得作为有效报告展示；AI 判断准确性须使用教师复核的独立样本验证，阈值待定 |

### P：性能

| 编号 | 需求与验收标准 |
| --- | --- |
| NFR-P-01 | 20 用户并发、持续 30 分钟时，任务列表与评分保存接口 P95 响应时间不超过 2 秒，系统错误率不超过 1% |
| NFR-P-02 | 720p 视频首帧 P95 不超过 5 秒；教师点击证据点后，目标画面呈现 P95 不超过 3 秒 |
| NFR-P-03 | AI 评估分别统计排队与推理耗时；单视频时限、并行任务数及每日吞吐根据模型与算力试测后确定 |

性能测试须记录硬件、浏览器、网络、视频规格及数据规模；测试前固定环境与操作频率。P95 为全部请求或操作耗时的第 95 百分位，接口统计不含视频传输和 AI 推理。

### S：支持性

| 编号 | 需求与验收标准 |
| --- | --- |
| NFR-S-01 | 评分与报告可追溯到视频、量表版本及评分员或评估批次；错误日志可关联具体任务且不含凭据或学生身份信息 |
| NFR-S-02 | AI 服务可替换为测试桩，不修改人工评分逻辑；覆盖正常、超时和非法输出场景 |
| NFR-S-03 | 实现后提供可复现的启动与测试说明；将越权访问、评分员 AI 信息隔离和评分保存纳入回归测试 |

## 2. 验收约定

每条需求记录测试环境、步骤、实际结果与证据；未确认指标标为阻塞，不记为通过。性能基线、AI 准确性阈值、备份恢复和数据留存政策须在试点前确认。
