## 2. 问题定义

### 2.1 核心问题

有经验教师的教学智慧不仅体现在最终的教案、题目或项目方案中，也体现在任务拆解、教学判断、操作顺序、约束条件和调整策略中。这些经验往往以默会知识存在，难以直接被其他教师理解和复用。

InnoSkill 希望解决的问题是：**如何降低教师将教学经验转化为 AI Skill 的门槛，让这些经验能够被分享、接入、执行和迭代，同时让职前教师及新手教师通过阅读 Skill 学习背后的教学方法？**

### 2.2 主要痛点与机会

| 问题假设 | 用户面临的困难 | 产品机会 |
| --- | --- | --- |
| Skill 创作门槛高 | 教师拥有教学经验，但可能缺少将经验组织成结构化、可执行 Skill 的方法与工具 | 提供模板填写、可视化编辑、AI 辅助生成与修改，以及已有 Skill 文件上传 |
| Skill 接入使用繁琐 | 分享的 Skill 与实际 AI 使用环境之间存在接入成本，用户需要自行理解配置与使用方式 | 支持平台内运行，并提供面向外部 AI 工具的接入能力与说明 |
| 缺少分享与反馈渠道 | 教学经验难以持续传播，使用者的问题和改进建议难以回流到创作者 | 建立 Skill 项目社区，支持 Star、Issue、Fork 与二次开发 |
| 默会知识难以被学习 | 仅获取 AI 生成结果，难以理解有经验教师为何这样设计教学 | 让 Skill 本身成为可阅读的经验载体，支持“使用技能”和“学习方法”两种价值 |

### 2.3 用户价值

- **对创作者**：降低经验表达与 Skill 创作的门槛，获得分享、反馈、协作改进和自主定价的渠道。
- **对使用者**：复用其他教师的教学方法，通过平台 AI 或外部 AI 工具执行 Skill，减少接入负担。
- **对职前教师及新手教师**：不仅获得教学任务的产出，还能阅读 Skill 中显性表达的方法、步骤与约束，学习经验教师的教学技巧。
- **对衍生创作者**：在授权允许的前提下 Fork 并二次开发已有 Skill，通过衍生作品贡献新的教学经验，并按收益规则获得回报。

## 3. 5W1H 报告

### 3.1 Who：为谁解决问题？

**主要面向中小学教师与职前教师。** 用户角色按参与行为划分，不要求互斥：

1. **Skill 创作者**：将自己的教学经验转化为 Skill，发布、维护并决定免费或收费。
2. **Skill 使用者**：发现并接入其他教师的 Skill，用于自身教学工作。
3. **经验学习者**：通过阅读 Skill，理解教学方法和设计逻辑，重点包括职前教师及新手教师。
4. **衍生创作者**：Fork 已有 Skill 并二次开发，形成可追溯的衍生作品。

平台运营方负责社区、平台 AI 服务、交易与收益分配机制的建设；具体审核、治理和争议处理职责待进一步定义。

### 3.2 What：产品是什么，要解决什么问题？

InnoSkill 是一个**教育 AI Skill 创作与分享社区**，而不是只提供备课、出题或 PBL 设计结果的单一教学工具。

本产品中的 Skill 指以文字化指令、方法、步骤和约束等形式承载教师经验、供 AI 执行且供人阅读学习的技能资源。具体文件格式、依赖声明及运行规范需在后续需求设计中明确。

核心能力包括：

- **创作**：模板填写、可视化编辑、AI 辅助生成与修改、上传已有 Skill 文件。
- **分享与发现**：发布 Skill，按分类与 Tag 组织内容；初始分类为备课、出题、PBL 设计，后续可扩展。
- **使用**：在平台自己的 AI 中运行，也支持接入外部 AI 工具。
- **社区协作**：通过 Star 表达认可，通过 Issue 反馈问题或提出建议，通过 Fork 开展二次开发。
- **学习**：阅读 Skill 中的教学方法与操作逻辑，而不只是获取执行结果。
- **商业化**：支持免费与收费 Skill、付费衍生作品收益分配，以及平台 AI 的 Token 用量计费。

### 3.3 Why：为什么值得做？

产品希望把教师个体积累的经验转化为可传播、可复用、可迭代的社区资源。

其价值不只是“让 AI 帮教师完成任务”，而是同时实现：

1. **经验显性化**：帮助创作者将默会知识表达为文字化 Skill。
2. **经验执行化**：让其他教师借助 AI 复用这些方法。
3. **经验学习化**：让新手教师能够阅读方法、理解过程并学习技巧。
4. **经验协作化**：通过 Issue 和 Fork 促进反馈与衍生创新。
5. **贡献激励**：允许创作者自主决定免费分享或收费，并使付费衍生作品中的上游贡献获得收益。

以上价值仍需通过真实教师的创作、使用和学习反馈验证，不能仅以 Skill 数量或生成结果数量判断成功。

### 3.4 Where：在哪里使用与传播？

- **InnoSkill 社区平台**：完成 Skill 创作、发布、分类浏览、阅读学习、Star、Issue、Fork 及交易。
- **平台自己的 AI 环境**：优先接入平台 AI，例如 InnoSpark，支持在平台内运行 Skill。
- **外部 AI 工具环境**：计划支持 WorkBuddy、Codex、Claude Code、pi-coding-agent、dsh、zcode 等工具。
- **教学与教师培养场景**：服务中小学教师的教学准备与设计，以及职前教师、新手教师的经验学习。

不同外部工具的 Skill 格式、执行能力与接入方式可能不同；上述名单表示接入目标，不代表已完成兼容验证，也不意味着所有工具具有相同的运行体验。具体支持版本、接入方式及兼容边界待验证。

### 3.5 When：何时交付，如何推进？

**预计于 2026 年 12 月 31 日交付。** 以下为围绕该目标的建议里程碑，具体阶段日期与交付范围待确认。

| 阶段 | 用户参与方式 | 主要产出与验证重点 |
| --- | --- | --- |
| 问题与需求确认 | 访谈中小学教师与职前教师，收集真实教学经验及现有分享方式 | 验证创作、接入和反馈痛点；明确 Skill 定义、首期范围与验收标准 |
| 原型与经验表达验证 | 邀请教师使用模板、可视化编辑和 AI 辅助方式创作样例 | 验证默会知识能否被清晰表达；验证新手教师能否读懂并学习 |
| 核心社区与运行闭环 | 邀请创作者发布 Skill，使用者在平台 AI 中运行并提交 Issue | 验证创作、发布、发现、阅读、运行和反馈的完整流程 |
| 外部接入与商业机制验证 | 邀请用户测试外部工具接入、免费与付费 Skill、Fork 衍生链路 | 确认兼容范围；验证定价、平台抽成、Token 计费与上游收益分配规则 |
| 交付验收 | 由目标用户完成代表性使用流程并反馈 | 在 2026 年 12 月 31 日前完成约定范围的交付；正式发布时间另行确认 |

### 3.6 How：如何解决问题并形成可持续机制？

#### 创作与复用流程

1. 教师通过模板、可视化编辑、AI 辅助或文件上传创建 Skill。
2. 创作者整理教学方法、步骤与约束，选择分类和 Tag，并设置免费或收费。
3. 用户浏览 Skill，阅读其方法与说明，选择在平台 AI 中运行或接入外部 AI 工具。
4. 用户通过 Star 表达认可，通过 Issue 提出问题与改进建议。
5. 在授权允许的前提下，其他创作者 Fork 并二次开发，形成衍生 Skill。

#### 收费与收益机制

| 场景 | 已明确的业务规则 |
| --- | --- |
| 免费 Skill | 创作者可以免费公开分享，平台不对该 Skill 收取交易抽成 |
| 收费 Skill | 创作者自主定价，平台对收费 Skill 的交易抽成；抽成比例待定 |
| 使用平台 AI | 平台向使用者收取 Token 使用费用；免费 Skill 不等于平台 AI 运行免费 |
| 使用外部 AI 工具 | 支持外部接入；外部工具或模型服务的费用不在本文中作统一承诺 |
| 付费衍生 Skill | 若 A 的原始 Skill 定价为 a，B 基于 A 的 Skill 创建衍生 Skill，并将新增部分定价为 b，则衍生 Skill 实际标价为 a + b；其中 a 对应 A 的收益部分，b 对应 B 的收益部分 |

付费衍生 Skill 的上述规则表达的是上游与衍生创作者的收益归属。平台抽成从何处扣除、创作者最终实收金额、Token 费用是否独立结算等细节，需另行明确，不能直接将 a、b 视为扣除所有费用后的净收入。

## 4. 产品描述与定位声明

### 4.1 产品描述

**InnoSkill，让教师智慧可读、可用、可传承。**

InnoSkill 是面向中小学教师与职前教师的教育 AI Skill 创作与分享社区。教师可以通过模板、可视化编辑和 AI 辅助，将自身教学经验转化为文字化 Skill，也可以上传已有 Skill，与其他教师分享或自主定价销售。

使用者既能在平台 AI 中运行 Skill，也能将其接入支持的外部 AI 工具；还可以像参与代码社区一样，通过 Star、Issue 和 Fork 表达认可、反馈问题及开展二次开发。平台以可扩展的分类与 Tag 组织资源，初期覆盖备课、出题和 PBL 设计，但不将社区限定于这些任务。

InnoSkill 的核心追求是“复现教师的智慧”：Skill 不仅是供 AI 执行的工具，也是供人阅读学习的经验载体，让职前教师与新手教师能够理解经验教师的方法，并在实践中复用、调整和发展这些方法。

### 4.2 定位声明

**对于**希望分享教学经验、复用他人方法，或学习教学技巧的中小学教师与职前教师，

**他们**需要降低 Skill 创作与接入的门槛，并获得持续分享、反馈和协作改进的渠道，

**InnoSkill 是一个**教育 AI Skill 创作、分享、复用与学习社区，

**它能够**通过模板与可视化编辑、AI 辅助创作、文件上传、平台内运行、外部工具接入，以及 Star、Issue、Fork 等机制，将教师经验转化为可阅读、可执行、可迭代的 Skill，并支持免费分享、付费交易和衍生收益分配，

**不同于**仅以最终教学材料交付为中心的资源平台、仅提供 AI 任务执行的工具，以及未专门围绕教师经验学习设计的通用 Skill 社区，

**InnoSkill 希望形成的关键差异化是**同时支持“执行教学方法”与“阅读学习教学方法”，将默会知识显性化，并通过社区协作与上游贡献收益机制促进经验传承和再创造。

上述对比是产品定位方向，不代表已完成竞品研究，不作“无竞品”“首创”或已验证优于竞品的结论。

## 5. 产品范围与边界

### 5.1 当前明确的目标范围

- 面向中小学教师与职前教师，不以某一单一教学任务定义产品。
- 支持教师创作、分享、使用和阅读学习 Skill。
- 支持模板、可视化编辑、AI 辅助创作和已有文件上传。
- 以备课、出题、PBL 设计为初始分类，分类与 Tag 可扩展。
- 同时支持平台 AI 运行与外部 AI 工具接入。
- 支持 Star、Issue、Fork 和二次开发。
- 支持创作者自主选择免费或收费、收费交易抽成、平台 AI Token 计费及付费衍生收益分配。

以上为产品目标范围，全部能力是否纳入首次交付及其优先级仍需在后续需求规格中确定。

### 5.2 尚待确认的关键问题

1. **Skill 技术规范**：文件格式、依赖、运行权限、可移植性，以及不同工具间的兼容策略。
2. **创作质量与教学价值**：如何判断经验表达完整、Skill 可用，以及阅读 Skill 是否确实有助于新手教师学习。
3. **版权与衍生授权**：免费或收费不自动等于允许 Fork、修改或再销售；需明确授权、署名、可见范围及侵权处理机制。
4. **付费内容与学习访问**：付费 Skill 的全文阅读权限、购买前展示范围，以及购买授权的期限和用途。
5. **交易与结算**：抽成比例、购买模式、退款规则、Token 定价、扣费展示及创作者结算方式。
6. **衍生链规则**：多层 Fork、多来源组合、上游价格变化、版本更新、删除或下架时如何处理授权、定价和收益。
7. **数据与运行安全**：教师或学生相关数据的使用边界，上传内容和 Skill 执行的权限控制及安全审核。
8. **交付验收**：首期具体功能、外部工具支持清单、质量标准、测试方式及正式发布时间。

## 6. 建议验证指标

以下为问题定义对应的验证方向，数值目标需在用户调研和原型测试后确定。

| 验证目标 | 建议观察指标 |
| --- | --- |
| 降低创作门槛 | 教师首次创建并发布 Skill 的完成率、耗时、所需协助及遇到的困难 |
| 降低接入成本 | 平台内首次运行成功率；各外部工具的接入成功率与操作耗时 |
| 促进分享与改进 | 发布后获得有效 Issue 的情况、问题处理情况及有实际改进的 Fork 案例 |
| 显性化教师智慧 | 创作者能否表达关键判断与约束；学习者能否解释 Skill 中的方法并用于新的教学情境 |
| 提供可用的教学帮助 | 教师对 Skill 执行结果的可用性评价、修改负担及持续复用情况 |
| 验证商业机制 | 价格和费用理解度、交易与收益分配准确性、创作者和使用者对规则的接受程度 |
