# InnoJudge 产品需求规格（草案）

## 1. 依据与状态

- 需求材料：`pdfdocs/` 下的物理实验评测 PRD（含多轮版本记录与评审评论），以及据此整理的[问题定义](problem_definition.md)。
- 材料对同一事项记录了多种决策状态（已确认、待讨论、互相矛盾的示例并存），本文按下列约定转述，不把任何单一文档当作唯一权威来源。
- 全仓代码目录（`code/frontend/`、`code/backend/`、`code/core_engine/`、`tests/`）仅有占位文件，**本文全部需求均未实现**；本文不描述已存在的接口、数据表或技术栈。

标注约定：

| 标注 | 含义 |
| --- | --- |
| **需求** | 从材料中整理出的目标能力，即“系统要支持什么”。仍需评审确认范围、优先级与验收细节 |
| **建议** | 本文补充的工程或流程设计，包括验收条件中涉及技术性约束的表述（如互不重叠、覆盖全长、入口隔离方式）。需评审确认后才进入验收 |
| **待确认** | 材料中标注待讨论，或材料内部互相矛盾、无法据以实现的条目。禁止按现有示例直接实现 |

## 2. 范围与优先级管理

- 首期基线为**离线优先**闭环：登录 → 建任务（四步）→ 上传视频 → 离线 AI 评估 → 评分员人工打分 → 教师查看人机对照。
- **实时流**：首期不依赖实时视频流与考场实时预览，后续单独评估（材料中既记录“4 月先做离线版本”，也记录“考场监控需支持实时预览”的诉求，未形成结论）。
- 其余候选能力（身份识别与考场核验、硬件反馈装置、评分员端展示 AI 评分入口、学生端反馈）在材料中均处于候选或待讨论状态，不进首期闭环，后续单独评估。
- 每个需求条目记录状态（未实现/待确认/暂不纳入）与依赖；未评审通过的能力统一为“待确认”。
- 需求 ID 按领域前缀编制：`AC` 账号与入口、`TK` 任务、`RB` 量表、`VI` 视频素材、`AS` 任务分配、`HG` 人工评分、`AI` 离线 AI 评估、`RP` 结果呈现、`SV` 权限与治理、`NF` 非功能约束；文档内以 `PR-` 前缀引用。

## 3. 需求清单

### 3.1 账号与入口（AC）

| 需求 ID | 类型 | 目标能力 | 验收条件 |
| --- | --- | --- | --- |
| PR-AC-01 | 需求 | 统一登录入口 | 未登录访问业务页面被拒绝并跳转登录；登录失败不透露账号是否存在；登录成功后进入与角色匹配的入口 |
| PR-AC-02 | 待确认 | 账号开通机制 | 材料一方面记录“平台只提供登录”，另一方面留有“是否所有账号都需要单独开通/注册”的待讨论问题，二者需先裁决；裁决前不实现自助注册，也不锁定邀请流程（与 PR-AC-05 相关） |
| PR-AC-03 | 需求 | 分层账号与角色区分（管理员/校领导、教师、评分员） | 角色可区分且入口可路由；同一账号拥有多角色时的入口切换与数据合并方式为**建议**（需评审），未确认前按单角色可用、跨角色不合并数据 |
| PR-AC-04 | 需求 | 后台用户管理 | 可创建、停用账号并授予角色；停用后不能再登录；账号管理入口仅对管理角色开放 |
| PR-AC-05 | 待确认 | 邀请评分员机制 | 材料提出“考虑邀请链接/邮件”，机制未定。决策后补：有效期、一次性使用、绑定角色与撤回方式 |
| PR-AC-06 | 需求 | 教师登录后可见任务入口 | 可见任务列表/看板与“新建评分任务”入口；无权限菜单不显示，直接请求同样被拒绝 |

### 3.2 评分任务与量表（TK / RB）

| 需求 ID | 类型 | 目标能力 | 验收条件 |
| --- | --- | --- | --- |
| PR-TK-01 | 需求 | 四步向导新建评分任务：①基本信息 → ②量表 → ③视频素材 → ④分配评分员 | 四步顺序可达且可返回修改；上一步未完成时给出明确原因并阻断下一步；取消不留下半成品任务 |
| PR-TK-02 | 需求 | 填写任务基本信息 | 任务名称可填写且为空时阻断；实验名称、截止时间、标签、年级/人数/主题等字段清单待确认，未确认前不实现其校验 |
| PR-TK-03 | 建议 | 草稿保存与继续编辑 | 草稿仅在任务列表显示为草稿，不进入评分员待评测列表；保存失败有提示且不覆盖上次成功保存内容 |
| PR-RB-01 | 需求 | 上传评分量表或选择已有量表 | 两条路径互斥且必须完成其一才能进入下一步；格式不支持或内容不完整时提示到具体条目 |
| PR-RB-02 | 需求 | 在选定量表基础上自主修改最终量表 | 可增删改评分项与子项并调整分值；修改只作用于本次任务；保存形成任务量表快照，后续量表库改动不影响已完成任务 |
| PR-RB-03 | 需求 | 量表分数结构可校验 | 评分项分值与其子项分值之和一致（不一致时阻断并指出条目）；分值非负；总分可计算 |
| PR-RB-04 | 需求 | 子项承载评分说明 | 每个子项含要求描述；满分标准、扣分说明、危险操作提示是否必填为**待确认**（材料中为占位内容）；为空时不得显示占位假文本 |
| PR-RB-05 | 待确认 | 量表层级与复用规则 | 是否允许两层以上层级、是否跨任务继承修改、是否版本化 |

### 3.3 视频素材（VI）

| 需求 ID | 类型 | 目标能力 | 验收条件 |
| --- | --- | --- | --- |
| PR-VI-01 | 需求 | 手工上传待评测视频 | 可多选上传；进度与结果可感知；格式、大小、中断等失败逐条说明并支持重试 |
| PR-VI-02 | 需求 | 视频与任务、被评对象建立对应关系 | 每个视频归属一个任务并可标识被评对象；未关联对象的视频不进入评分任务 |
| PR-VI-03 | 建议 | 上传与视频来源解耦 | 后续接入其他来源（含实时流）时不必改动评分与结果逻辑 |
| PR-VI-04 | 待确认 | 视频规格验收基线 | 材料仅记录现状（约 1 s/帧、720p、单视频 10–30 分钟、通常小于 1G），哪些作为硬性校验待确认 |
| PR-VI-05 | 需求 | 视频访问受控 | 视频不可通过猜测地址匿名访问；未登录或越权请求被拒绝 |

### 3.4 任务分配（AS）

| 需求 ID | 类型 | 目标能力 | 验收条件 |
| --- | --- | --- | --- |
| PR-AS-01 | 需求 | 把具体评分任务分配给评分员 | 可选择评分员并分配指定视频/被评对象，分配后出现在该评分员待评测列表 |
| PR-AS-02 | 建议 | 重复分配的处理 | 同一评分员被重复分配同一对象时提示或去重，统计口径只计一次 |
| PR-AS-03 | 需求 | 分配可收回或改派 | 收回后该评分员不能继续提交；已提交的人工评分不被静默删除，需保留并标注状态 |
| PR-AS-04 | 待确认 | 分片与多人评分汇总 | 一个评分员评全部还是部分题、多人分数取平均或其他方式，均待决策（BR-04） |

### 3.5 评分员人工评分（HG）

| 需求 ID | 类型 | 目标能力 | 验收条件 |
| --- | --- | --- | --- |
| PR-HG-01 | 需求 | 待评测任务列表 | 仅列出分配给我的对象；已完成与未完成状态可区分；不出现任何 AI 信息 |
| PR-HG-02 | 需求 | 按量表逐项打分 | 按“评分项 → 子项”展开；每个子项可给分（0 ≤ 得分 ≤ 子项满分）并可填写意见 |
| PR-HG-03 | 需求 | 边看视频边打分并保存 | 可播放、暂停、拖动定位；未提交内容可保存草稿；保存失败不丢失已填分数 |
| PR-HG-04 | 需求 | 评分员不可见 AI 评估结果 | 评分员可见的页面、接口响应、列表摘要与导出内容均不含 AI 分数、AI 反馈、AI 错误标注或其时间区间；越权请求被拒绝 |
| PR-HG-05 | 需求 | 提交结果可追溯 | 记录评分员、量表快照版本与提交时间；提交后是否可修改为**待确认**，未确认前按不可修改处理并在界面说明 |
| PR-HG-06 | 待确认 | 已完成任务是否在评分员列表显示 | 决策后补：显示方式与是否允许查看本人历史评分 |
| PR-HG-07 | 建议 | 人工端的定位辅助 | 人工端是否显示 AI 阶段分解以辅助定位，需需求侧明确批准；当前默认不显示（与 PR-HG-04 一致） |

### 3.6 离线 AI 评估（AI）

| 需求 ID | 类型 | 目标能力 | 验收条件 |
| --- | --- | --- | --- |
| PR-AI-01 | 需求 | 离线批量评估上传的视频 | 不依赖实时流；评估期间视频仍可被人工评分；触发方式（自动/手动）**待确认** |
| PR-AI-02 | 需求 | 产出阶段分解 | 返回阶段列表，每段含名称、颜色标识、开始与结束时间；按开始时间升序、互不重叠、覆盖视频有效时长属**建议**约束，需与模型侧确认后才作为验收项 |
| PR-AI-03 | 需求 | 产出错误操作标注 | 返回错误条目，含名称、类型（至少区分一般错误与严重错误）、开始与结束时间；起止相同表示时间点标注，界面可显示 |
| PR-AI-04 | 需求 | 产出 AI 报告 | 报告含总述、总分、分项与子项反馈；每个子项含状态标识与文字反馈 |
| PR-AI-05 | 需求 | 结果可溯源 | 每条 AI 结果绑定视频、任务量表快照与评估批次；量表或视频变更后旧结果不被静默复用 |
| PR-AI-06 | 需求 | 评估过程可观察、可恢复 | 状态（排队/运行/成功/失败）可查，失败原因可见，可重跑；重跑不覆盖已提交的人工评分 |
| PR-AI-07 | 待确认 | AI 返回字段定版 | 材料示例存在矛盾（总分与报告分数不一致、子项得分超过满分、`AIscore` 与 `minus` 并存、`label` 枚举不完整），须与模型侧统一字段含义和校验规则 |
| PR-AI-08 | 建议 | AI 结果不参与人工评分与最终成绩计算 | 人机结果并列展示并分别标注来源；不产生混合来源的单一分数，除非公式经批准 |

### 3.7 结果呈现（RP）

| 需求 ID | 类型 | 目标能力 | 验收条件 |
| --- | --- | --- | --- |
| PR-RP-01 | 需求 | 查看某评分任务下某段视频的人机评分结果 | 同一页可分别查看 AI 报告与人工评分，来源标识清晰、不混淆 |
| PR-RP-02 | 需求 | 点击评分点跳转到对应视频阶段 | 点击可定位的评分项/子项后视频定位到对应阶段起点；无对应区间时提示“无对应片段”，不静默不动 |
| PR-RP-03 | 需求 | 阶段分解时间轴 | 按阶段顺序展示名称与区间，可点击定位，颜色标识与阶段对应 |
| PR-RP-04 | 需求 | 错误操作标注展示 | 错误条目按时间排序、可点击定位，一般错误与严重错误可区分 |
| PR-RP-05 | 建议 | 人工与 AI 差异视图 | 可并列同一条评分项的人工得分与 AI 得分；差异以列表呈现，不自动判定谁正确 |
| PR-RP-06 | 待确认 | 报告图片/截图链接 | 材料记录“补充图片的链接”“图片是 html”，用途与格式待确认 |
| PR-RP-07 | 待确认 | 看板指标 | 校级/项目级看板字段与统计口径在材料中均标注待讨论，未确认前不实现具体指标 |
| PR-RP-08 | 需求 | 结果展示不作为 AI 泄漏渠道 | 结果页不对评分员角色开放；含 AI 内容的导出或分享仅限有权角色 |

| --- | --- | --- | --- |
| PR-SV-01 | 需求 | 按角色限制可见范围与操作 | 评分员仅访问分配给自己的对象；教师与管理员范围待权限矩阵确认（BR-06）；越权请求被拒绝 |
| PR-SV-02 | 需求 | 关键操作留痕 | 账号创建/停用、角色变更、任务发布、分配与收回、人工评分提交、评估重跑可查，记录含操作者、时间与对象标识 |

| 需求 ID | 类型 | 约束 | 验收方式 |

## 4. 代表性验收场景

1. **四步建任务**：创建任务 → 上传新量表 → 修改某子项分值 → 上传两段视频并关联对象 → 分配给两名评分员；中途返回上一步不丢已填内容；评分项与子项分值不一致时被阻断。
2. **评分员隔离**：评分员完成一次完整打分；同时以该身份直接请求结果类接口，全部被拒绝；页面与响应中检索不到 AI 分数与 AI 反馈字段。
3. **证据跳转**：教师点击“多点测量”子项，视频定位到该阶段起点；点击起止相同的错误标注仍能定位到该时间点。
4. **重跑不污染**：评估失败后重跑成功；已提交的人工评分保持不变；重跑结果与量表快照版本可对应查证。
5. **越权与旁路**：修改 URL 中的任务或视频标识访问他人资源被拒绝；导出文件不含无权内容。
6. **待确认项不假实现**：未定版的 AI 字段与看板指标以明确状态呈现，不返回臆测数值。

## 6. 质量与验证

- 需求条目的验收条件须能转化为可执行测试用例；无法验证的表述不进入验收基线。
- 关键质量属性：评分员侧零 AI 泄漏、人工与 AI 结果不混合成单一分数、AI 结果可溯源、越权访问被拒绝、量表分值与报告分数一致。
- 数值型指标（耗时、一致性、吞吐）需首轮真实任务后确定，不在本文虚构。
- 测试用例应关联需求 ID，记录实际结果与未覆盖项。
