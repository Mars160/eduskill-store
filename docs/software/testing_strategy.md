# InnoSkill 测试与验证策略（草案）

## 1. 状态与依据

- 依据：[问题定义](../requirements/problem_definition.md)、[产品需求](../requirements/product_requirements.md)。
- 设计边界参考[逻辑架构](architecture.md)，阶段门槛参考[路线图](../mgmt/roadmap.md)。
- 当前按尚无可运行代码的阶段制定策略；本文不声称任何测试已执行或通过。
- 不提供虚构的启动、构建或测试命令；选型和实现后再补充可复现执行说明。
- 验证覆盖目标需求，不代表所有需求均已纳入首期；排除项须记录理由并批准。
- 未决规则对应的预期结果标记为“阻塞”，不能以测试人员的猜测替代业务决策。

## 2. 验证分层

| 层次 | 当前可做 / 后续计划 | 主要证据 |
| --- | --- | --- |
| 需求评审 | 当前可核对需求、角色、规则冲突与边界 | 评审记录、未决项清单 |
| 原型与用户验证 | 有原型后邀请教师完成任务并解释方法 | 观察记录、脱敏样例、反馈 |
| 领域规则测试 | 实现后验证授权、定价、收益及状态转换 | 用例、输入、期望与实际结果 |
| 适配契约测试 | 接口确定后验证 AI、工具、支付和计量契约 | 契约版本、模拟与真实环境证据 |
| 集成与端到端 | 可运行后验证跨模块闭环及失败恢复 | 环境、版本、操作记录与报告 |
| 安全与非功能 | 按风险与批准指标验证权限、隔离、性能和恢复 | 检查报告、缺陷与复测记录 |

模拟测试不能代替真实外部兼容验证；AI 输出不能只凭字符串相等判定教学价值。

## 4. 商业收益专项

- 免费 Skill：验证交易抽成为零；平台 AI Token 费用另按批准规则处理。
- 收费 Skill：核对展示价格、订单快照、抽成依据、创作者归属与最终实收。
- 单层付费衍生样例：a=10、b=4，标价应为 14；这是测试数据，不是产品定价。
- 上述样例上游归属为 10、新增部分归属为 4；不能将其直接断言为净到账金额。
- 抽成比例与扣除位置未定时，仅验证标价与归属；净收益用例保持阻塞。
- Token 测试区分输入与输出等计量维度是否适用，计价口径以批准规则为准。
- 同一订单重复回调、请求重试、乱序事件不得重复赋权、入账或分配收益。
- 支付成功但授权失败、计费失败但执行完成等场景，应可恢复并对账。
- 退款对授权、上下游收益和已结算金额的影响，须待规则确定后验证。
- 多层、多来源、上游改价、版本更新、下架与删除均作为独立待决测试组。
- 小数精度、舍入、币种、负数、零价及金额上限待规则明确后覆盖。
- 核对“订单金额、抽成、分配、退款、结算”之间守恒关系；公式必须有批准依据。

## 5. 权限与安全专项

| 场景 | 需要验证的边界 |
| --- | --- |
| 作者与非作者 | 编辑、发布、改价和维护权限不能通过修改资源标识绕过 |
| 未购买与已购买 | 预览、全文、下载、运行、导出分别鉴权；购买不自动包含全部权限 |
| 免费但禁止衍生 | 可访问权限不自动赋予 Fork、修改或再销售许可 |
| 多角色账号 | 创作者、学习者等参与角色不带来额外运营权限 |
| 外部工具接入 | 导出不能绕过付费与许可限制；凭据不写入导出包 |
| 运营人员 | 按职责限制审核、下架和财务操作；关键动作留痕 |
| 上传与执行 | 路径越界、危险依赖、提示注入、未授权工具调用均受控 |
| 隐私与日志 | 教师、学生数据及密钥不进入公开内容、普通日志或共享测试证据 |

负向用例应覆盖直接请求、搜索摘要、历史版本、错误信息和外部导出等旁路。

## 6. 教学价值与用户验证

- 邀请中小学教师、职前教师及新手教师，使用脱敏的真实教学情境。
- 观察首次创作完成率、耗时、求助与卡点，不预设样本规模或成功阈值。
- 检查 Skill 是否表达关键判断、条件、步骤与适用边界，而非仅有生成指令。
- 让学习者解释设计理由并迁移到新情境；不以“能读到全文”等同于学会方法。
- 由教师评价运行结果的可用性、教学约束和修改负担，记录意见分歧。
- 验证价格、Token 费用与衍生收益的理解度，不以点击购买证明规则被理解。
- 数值门槛及抽样方案由需求负责人和目标用户代表确认后纳入验收基线。

## 7. 执行、缺陷与准入

- 用例记录需求 ID、规则版本、环境、数据、操作步骤、预期结果与证据。
- 外部测试记录工具及模型版本、适配方式、费用来源与已知限制。
- 未开始、通过、失败、阻塞、排除分别记录；不能把阻塞记作通过。
- 缺陷关联需求与风险；越权、隐私泄露、重复扣款和收益错误应优先处置。
- 实现后建立回归集，优先覆盖授权、财务幂等、版本追溯与核心闭环。
- 交付前：范围已签署、规则已解决或明确排除、证据可复现、关键风险已处置。
- 对首期范围内尚未通过的关键验收项，不得用演示或模拟结果替代正式验收。
- 测试报告需列出未覆盖项与残余风险，由相关负责人明确接受或阻止交付。
